# 시나리오 드라이버 구동 증거 (2026-08-13)

`docs/qa/SCENARIOS.md`에 적힌 **문서화된 호출만으로** 전 시나리오를 끝까지 구동한 기록입니다.
`capture.mjs`는 `localStorage`를 손으로 심지 않습니다 — `?scenario=<이름>` 과
`__aitSetTimeTravelDate` + `location.reload()` 만 씁니다. (대조: `../evidence-fusion-final/capture.mjs`는
융합 가능한 마을에 도달할 다른 방법이 없어 건물 4채와 core/index 블롭을 직접 써넣어야 했습니다.
그 손질이 바로 이 드라이버가 없앤 것입니다.)

## 재실행

```bash
npm run dev            # 별도 터미널, :5173
PW_PACKAGE=<abs>/node_modules/playwright/index.mjs node capture.mjs --base http://localhost:5173
```

`playwright`는 의도적으로 이 앱의 의존성이 아닙니다 — 기존 설치를 가리키세요.
공용 머신 규칙: 자신이 띄운 dev 서버 PID만 종료하고, 이미지 이름으로 죽이지 마세요.

## 구동으로 드러난 실제 결함 후보

**FT-1 — 만원 마을의 이연 공원은 지켜질 수 없는 약속을 매일 반복한다.**
지도가 만원인 상태에서 `오늘 무지출!`을 청구하면 앱이
`공원은 내일 아침에 지어드릴게요` 라고 약속하고 헤더에 `내일 지을 건물 1개 대기 중`을 붙입니다.
그런데 다음 날 아침으로 넘겨도(`__aitSetTimeTravelDate("2026-08-11"); location.reload()`)
지도는 여전히 만원이라 소진이 배치할 자리가 없고, **건물 수는 80 그대로, 같은 약속 문구가 다시 뜹니다.**
지도에 자리가 나기 전까지 무기한 반복됩니다.

- 코드상 오동작은 아닙니다(소진은 자리가 없으면 큐를 보존하는 게 맞습니다). 빠진 것은
  **약속을 지킬 수 없다는 사실을 플레이어에게 알리는 문구**입니다.
- 재현: 위 `full-town` 절차. 증거: `18-full-town-park-deferred.png`, `19-full-town-next-morning.png`.
- 이 세션에서 고치지 않았습니다 — 문구/UX 판단이 필요하고, 발견 자체가 이 작업의 목적이었습니다.
