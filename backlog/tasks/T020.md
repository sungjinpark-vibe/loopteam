## Brief
Director decision (2026-08-09, verbatim intent): a building gains **EXP**. When the player saves a
ledger entry whose category already has at least one standing building, a popup asks:
(a) build a NEW building, or (b) add EXP to an EXISTING one. When several buildings of that category
exist, the player picks which one. When no building of that category exists yet, no popup — build a
new one exactly as today (no needless taps).

This is the director's answer to Gate-3 finding #1 (reward decoupled from the money amount) — partially:
it adds **agency**, not amount-sensitivity. Amount-proportional EXP is prepared as a dial but left OFF
pending the director's answer (see "Open question" below).

Design spec: `app_in_toss/docs/spec/ADDENDUM-04-building-exp.md`.

## Acceptance criteria
- [ ] `Building.exp?: number` added, optional, absent = 0. **No storage migration step** — existing
      buildings read as exp 0 and the town's tier is unchanged on first load after update.
- [ ] Tier counts a **growth score** = `buildings.length + Σ exp`, not `buildings.length`. Every act
      (new build OR grow) adds exactly 1, so tier pacing is identical to today and neither choice is
      punished. All existing tier call sites go through the one selector.
- [ ] Saving an entry with an existing same-category building AND a free build slot shows a 2-choice
      dialog. No same-category building, or no free slot (queue path), or 저축 type → no dialog.
- [ ] Exactly one same-category building + "키우기" → grows it immediately, no second step.
      Two or more → grid pick mode: candidates highlighted, tap one to grow, back/cancel aborts
      without saving.
- [ ] Growing consumes a build slot and advances the streak exactly like building (F4/F7 unchanged —
      growing must not be a free bypass of the daily cap).
- [ ] Growing creates no new plot: `nextPlotIndex` is not incremented, no lot opens.
- [ ] The entry links to the grown building (`entry.buildingId = host.id`); F9 delete and
      지출/수입→저축 conversion back the EXP out of the host instead of removing it.
- [ ] Level = `1 + floor(exp / expPerLevel)`, visible on the tile (taller building, level badge),
      capped visually at `maxLevel`; EXP past the cap still counts toward tier.
- [ ] Tests: pure-logic (entryActions/historyActions/selectors), store wiring, dialog + pick-mode
      component tests. Gate 1 (`gate/gate-node.ps1`) fully green.
- [ ] Live browser evidence via `evidence.mjs`: no-popup first build, popup on second same-category
      save, both branches, multi-candidate pick, level visual change.

## Open question for the director (do not decide autonomously)
Should EXP gained scale with the entry's ₩ amount? Dial is written (`BALANCE.expAmountTiers`), default
OFF (flat 1 per act). See ADDENDUM-04 §7 for the two candidate tables and the caveat that scaling EXP
on 지출 rewards big spending, which may be backwards for a budgeting app.
