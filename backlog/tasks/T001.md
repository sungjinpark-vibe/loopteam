## Brief
Turn the director's brief into a detailed MVP spec for a Toss mini-app: a household ledger (가계부)
app whose core loop is inspired by **Fortune City** — a real budgeting app where tracked
spending/saving grows a visible city. Research the actual Fortune City app (store listings, reviews
describing its loop) before designing — the point is to adapt what makes that loop work, not to
invent a generic "collect stuff" loop and call it Fortune City.

Platform: Toss mini-app (React + TypeScript + Vite + Toss Design System, scaffolded via
`npx create-ait-app`) — non-game category. See `app_in_toss/VISION.md` for the full project contract
and stack notes.

No Toss developer account/business registration exists yet and won't for a while — the spec must
define an MVP that is fully buildable and demoable via local dev (`vite` dev server), with any
Toss-account-gated SDK calls (real payments, Toss Login, etc.) either deferred or mocked. Manual
ledger entry, not real bank-linked data, is the safe default scope for MVP.

## Acceptance criteria
- [ ] Core loop defined end to end: user logs a financial entry (expense/income/saving) → some
      visible town/village state changes as a direct result → the player can see cumulative progress
- [ ] Screen list for MVP (minimum: ledger entry, town/village view, history/stats) with what each
      screen must do
- [ ] Data model for ledger entries + village/growth state
- [ ] Explicit mapping from Fortune City's actual mechanic to this app's mechanic — cite what's
      borrowed and what had to change for a real financial-habit app, not a cosmetic reskin
- [ ] MVP scope vs later scope clearly separated — no store/Toss review dependency, no real
      bank-linked data required for MVP, no dependency on business-registration/console access
- [ ] Toss platform constraints acknowledged: which SDK capabilities (payments, storage, analytics,
      Toss Login, etc. — see dev docs) the MVP actually uses vs explicitly defers
- [ ] Open decisions surfaced for the director — do not invent an answer where one is genuinely the
      director's call (naming, monetization, whether real bank sync is ever in scope, etc.)
