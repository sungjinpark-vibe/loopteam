## Brief
Implement `app_in_toss/docs/spec/ADDENDUM-01-savings-and-roads.md` §2 — the 저축 블록 (savings block)
itself: five real structures (예적금/주식투자/비상금/목표저축/기타저축) replacing the empty-lot
placeholders `SavingsRow.tsx` currently renders. The road/cell layout and the shared growth-geometry
functions were already built by earlier tasks — this task is content + wiring, not layout.

**Already done, read before writing anything new:**
- `src/components/SavingsRow.tsx` — renders the 5 cells as `.savings-plot--empty` + one signpost.
  Its own header comment says exactly what the next task (this one) must swap in: real
  `.savings-structure*` markup per §2.4a, plus `ladderOverrides`/`savingsByCategoryKrw`/`justGrew`
  props (currently only `ladder` is wired).
- `src/townLayout.ts` — `savingsCellFor`, `roadSideOf`, `districtLadderLength`,
  `savingsPlotHeightPx`, `savingsPlotTemplateRows`, `SAVINGS_ROW_ORDER`, `freeSavingsCells` all exist
  and are geometry-complete.
- `src/selectors.ts` — `ladderFor` and `towerSegments` already exist (shipped with the road task per
  ADDENDUM-01 §4.2's corrected task split). **Missing**: `savingsByCategory`, `grownStructures` — add
  these here.
- `src/types.ts` — `SavingCategoryId` already includes `"deposit" | "stock"` alongside the legacy
  `"emergency" | "goal" | "invest" | "other_saving"`. **`"invest"` is not yet retired/aliased** — do
  that here (§4.4/§4.5's `LegacySavingCategoryId`/alias handling).
- `src/savingsBuckets.ts` exists (`SAVING_CATEGORY_IDS`, `savingsBucketOf`, etc.) — shipped with the
  road task, use it, don't duplicate it.
- `src/components/EntrySheet.tsx` — the 저축 segment is currently `disabled` (intentional — nothing
  to wire it to yet). Enable it here.

**What this task actually builds:**
- `SAVINGS_STRUCTURE` (§2.3) — the per-structure visual contract: kind, capShape, idleAnim, signboard,
  emptyHint, levelUpToast, for all five ids.
- Real `.savings-structure*` DOM per §2.4a's class contract, replacing `SavingsRow`'s current empty
  skeleton — full `SavingsRowProps` (`ladder`, `ladderOverrides`, `savingsByCategoryKrw`, `justGrew`)
  per §3.4's `TownGridProps`/break B14.
- `selectors.ts`: `savingsByCategory` (per-id cumulative KRW → level, using `ladderFor`) and
  `grownStructures` (level-up detection between two `savingsByCategory` snapshots).
- `entryActions.ts`'s 저축 branch: accumulate into `savingsByCategoryKrw` on save, using
  `savingsBucketOf` for the id narrowing (§4.5a — the exact mechanism is already specified there).
- Level-up detection + toast wiring through `useTownStore`'s existing Notice FIFO (mirrors how T010
  wired the move-hint notice — reuse that pattern, don't invent a second one).
- `devtools/fixtures.ts`: populate `savingsByCategoryKrw` in fixtures so they don't boot with a
  non-zero 저축 total next to five empty structures (a gap the addendum's own compatibility section
  flags — check §5.2/§7 for the exact fixture rows needing this).
- Legacy `"invest"` id handling per §4.4/§4.5 (alias, don't just delete — existing data may reference
  it).
