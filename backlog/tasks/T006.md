## Brief
Implement the road layout half of `app_in_toss/docs/spec/ADDENDUM-01-savings-and-roads.md` — §3
specifically (§2, the savings buildings themselves, is a separate follow-up task; this task only
prepares the grid cells they'll occupy). Per the addendum's own build order (§6): **this task is
independently demoable — the director should see an actual village, with roads, the same day this
lands.**

**Step 0 — component test harness** (§6 row 1, prerequisite): the repo has no component test yet.
Add one shared mount helper (`createRoot` + `act`, the same pattern already used in
`useTownStore.test.tsx`) and the first `src/components/*.test.tsx`. No new dependency needed. This
unblocks every `[dom]`-tagged AC below.

**Step 1 — read the addendum's road sections directly**, they are fully worked (exact function
bodies, worked values, CSS): §3.1 (architecture), §3.2 (block plan), §3.3 (`src/townLayout.ts`, new
file — `cellFromIndex`/`indexFromPlot`/frontage invariant/etc), §3.4 (`TownGrid.tsx` rendering, CSS
grid only), §3.5 (`App.css`, and **rule R-3**: layout constants live in TS, never duplicated in CSS),
§3.6 (layout-vs-decoration boundary), §3.9 (the F2 screen-adjacency AC — `SERPENTINE_COLUMNS` ships,
preserving "index 6 directly below index 5" on screen, per the PM's resolution of D-30).

**Step 2 — also carries** (per the PM's post-review correction in §4.6/§6 of the addendum — read that
correction, it changes which task owns which file vs. the addendum's earlier draft):
- `src/savingsBuckets.ts` (NEW, §4.5) — lands HERE, not with the savings-buildings task, because
  `townLayout.ts` imports `SAVING_CATEGORY_IDS` from it.
- `ladderFor` appended to `src/selectors.ts` (§4.2) — also lands here, needed for savings-row height
  sizing. `savingsByCategory`/`grownStructures` do NOT land here — those are the savings-buildings
  task.
- `src/storage.ts`: `LAYOUT_VERSION` field + comparison at boot (§4.6).
- `src/App.tsx`: one new notice branch for the one-time `relayout` toast (§4.6, break B8).
- The savings block's **cells** render as empty lots + the 안내판 signpost (NOT the actual structures
  — those come in the next task). See the addendum's "Ordering note" in §6 for exactly why the cells
  ship here.

**What must NOT change**: `plotFromIndex`, `TOWN_COLUMNS`, and `nextPlotIndex`'s allocation logic in
`selectors.ts`/`entryActions.ts` — the addendum's whole architecture rests on this staying untouched
(the appends above are fine; modifying the allocator itself is not). §5.5 (rescoped evidence rule)
states exactly what Gate 1 evidence must show.
