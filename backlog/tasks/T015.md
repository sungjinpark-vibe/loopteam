## Brief
Fix two known, already-diagnosed bugs logged during T012/T013's reviews. Both are small and don't
need any director decision — pure bug fixes on top of the now feature-complete MVP.

**1. TDS nested-dialog backdrop becomes unresponsive after cancelling a nested confirm.**
Found twice (T012's `EntryDetailSheet` delete-confirm, T013's `SettingsSheet` 데이터초기화 confirm):
opening a sheet's own nested `ConfirmDialog` and then cancelling it leaves the outer `BottomSheet`'s
backdrop/dimmer unresponsive to a subsequent tap — its full-viewport overlay's geometry appears to
collapse. Confirmed via `document.elementFromPoint` in T013's review that the identical defect exists
in both places, same TDS `BottomSheet` + `ConfirmDialog` nesting pattern. The actual keyboard/back
gesture path still works in this state (only the backdrop tap is affected). Investigate the TDS
component interaction (check for a known workaround — re-mounting the dimmer, a z-index/stacking
issue, or an event-handler that needs re-binding after the nested dialog unmounts) and fix it at the
shared root cause, not by patching each sheet separately if avoidable — check if there's a shared
hook/wrapper (`useBackGuard` or similar) where a fix would cover both call sites at once.

**2. Month navigation in 기록 briefly flashes the empty state before real data paints.**
`HistoryScreen.tsx`: `ensureMonthLoaded(ym)` runs in a `useEffect` (after paint), while
`getMonthEntries(ym)` reads during render — so the first commit for a newly-navigated-to month always
sees `entries === []` and renders the "이 달엔 기록이 없어요" empty state for one frame before the
real data appears. `ensureMonthLoaded` is a fully synchronous function (one `localStorage.getItem`).
Fix by loading synchronously during render (or via `useLayoutEffect`, or restructuring so
`getMonthEntries` triggers the load itself) — pick whichever is cleanest without breaking the
existing memoization/dense-fixture performance work from T012.
