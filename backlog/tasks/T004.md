## Brief
Spec build order (§12) step 3: **F4 slots, F7 streak, F5 tier, F14 queue, F15 무지출 데이 — the
retention layer.** All five are grouped in the spec's own build order because they interact (a slot
reset gates the queue drain, a claimed no-spend day both consumes a slot and counts as a streak act).
Read §5 directly for F4, F5, F7, F14, F15 (full behavior + AC for each) and §9 for the exact balance
keys already defined in `src/balance.placeholder.ts` from T002 (`dailyBuildSlots`, `materialQueueMax`,
`tierThresholds`, `noSpendDayCostsSlot`).

Build on T002/T003's existing code — `src/types.ts`, `src/selectors.ts`, `src/storage.ts`,
`src/balance.placeholder.ts`, and the S2/S4 components already exist. Read them before writing
anything new. Remember `loadBoot()` is `async`.

**What must actually work end to end, in order:**
1. **F4** — `slotsUsedToday` resets when the clock port reports a date later than
   `town.slotsUsedOn`, evaluated on app open and on every save. No timers/background jobs.
2. **F14** — on app open, **after** the F4 slot reset, drain the queue in FIFO order up to that day's
   slot count, building and consuming slots exactly as a normal save would (staggered animation is a
   nice-to-have, not required for this task — a plain sequential appearance is fine). When a save
   happens with zero slots remaining, push to the queue instead of failing; show the toast text from
   §5 F14 (the "내일 아침에 지어드릴게요 (대기 N개)" line, or the overflow line if `queue.length` is
   already at `materialQueueMax`).
3. **F5** — `tier = f(buildingCount)` via `tierThresholds`; crossing a threshold upward on save
   triggers a one-time celebration (a simple full-screen overlay is enough — do not over-build the
   animation), then returns to the town. `highestTierSeen` guarantees once-per-threshold; deleting
   entries can lower the displayed tier but must not re-trigger the celebration on the way back up
   past an already-seen threshold.
4. **F7** — `streakDays` increments on the first build-producing act of a calendar day (an entry that
   builds/queues, or a claimed no-spend day) if the previous act day was yesterday; resets to 1
   otherwise. `longestStreakDays` never decreases. Show it in the S2 header.
5. **F15** — the town screen offers **[오늘 무지출!]** when today has zero 지출 entries,
   `slotsRemainingToday > 0`, and today isn't already claimed. Claiming consumes one slot (per
   `noSpendDayCostsSlot`), places a park-tile building (reuse `PlaceholderBuilding`'s existing
   category-colour/icon/roof interface — categoryId can be a new `nospend` kind per `types.ts`),
   records the date in `noSpendDays`, and counts as a build-producing act for F7. Implement the
   revocation rule from §5 F15 exactly (logging a 지출 for an already-claimed date removes the claim;
   refund the slot only if the revoked date is today).

**Out of scope for this task** (later steps per the build order): F13 저축탑, F16 monthly settlement,
F17 memo chips, real art, S3 (기록/history tab).
